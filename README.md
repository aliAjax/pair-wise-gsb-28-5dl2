# 配送排班与逆向回仓闭环

- 行业：物流
- 技术栈：React、Vite、TypeScript
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

在配送排班（待分配 → 已分配 → 已签收）之上补齐逆向回仓闭环：

1. **拒收/售后生成回仓单**：记录原订单、取件时段、司机、车辆和原因；拒收同时生成只读「拒收单」。
2. **唯一有效回仓单**：同一订单同时只能有一张有效回仓单（待取件/待复核），重复开单被拦截。
3. **时段占用校验**：司机在取件时段已有任务（已分配配送单或有效回仓单）时不能接单。
4. **重量复核**：回仓重量与原单不一致时转入「待复核」，复核通过才能完成。
5. **完成闭环**：回仓完成自动释放司机时段，并生成带原因的修订（REV-n）；原签收单只读、不可改写。
6. **冲突可追溯**：所有被规则拦截的操作都会记录订单、司机、时段和触发规则。

订单、回仓单、签收/拒收单、修订链、冲突记录整体持久化在 localStorage（`hxwlfront-14-schedule`，带版本号），刷新后排班、回仓状态与修订链保持一致。页面右上角「重置演示数据」可恢复初始种子数据。
